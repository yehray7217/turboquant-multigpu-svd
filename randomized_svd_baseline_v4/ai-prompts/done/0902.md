# Task 1 — Fix --check-b-error so it is diagnostic-only

Current problem:

--check-b-error may change the main computation path. In the B compression path, some decoded payloads may be used for diagnostics but skipped from accumulation into the final B.

This must be fixed.

Required behavior:

- --check-b-error on and --check-b-error off must produce the same final B_compressed.
- The only difference should be that --check-b-error on prints extra diagnostics.
- Diagnostic decoding must never prevent decoded data from being accumulated into d_B.

Implementation requirement:

Do not use a single boolean such as decoded_payload_on_gpu0 to mean both:

1. payload is already resident on GPU0
2. decoded matrix has already been accumulated into d_B

Instead, split the state into two meanings, for example:

    bool payload_on_gpu0 = false;
    bool accumulated_to_B = false;

Then ensure the logic is:

    if (check_b_error) {
        decode into diagnostic buffer;
        compute local B error;
    }

    if (!accumulated_to_B) {
        decode if needed;
        add decoded B contribution into d_B;
        accumulated_to_B = true;
    }

Acceptance test:

Run the same seed/config with and without --check-b-error.

Expected:

- Final reconstruction error should be identical or within numerical roundoff.
- Final B path should not change.
- Extra B Relative Error / diagnostic output appears only when --check-b-error is enabled.

# Task 2 — Fix or disable tq-qjl

Current status:

mode=tq has been migrated to Lloyd-Max codebook quantization.

However, mode=tq-qjl may still be using the old uniform max-abs quantization path or an older prototype. This is dangerous because it can be mistaken for faithful TurboQuant-prod / QJL.

For this patch, choose the safer option:

## Disable tq-qjl explicitly

Required behavior:

- If user requests mode=tq-qjl, fail loudly with a clear error message.
- Do NOT silently fall back to tq.
- Do NOT allow tq-qjl results to be reported as valid.

Suggested error message:

    mode=tq-qjl is currently disabled: Lloyd-Max + QJL residual correction is not implemented in the current faithful path.

Rationale:

Faithful TurboQuant-prod should be:

    MSE quantizer with b-1 bits using Lloyd-Max codebook
    +
    1-bit QJL residual correction

If this is not implemented, the mode should not be available.

Do not attempt a full QJL rewrite in this patch unless it is already straightforward and fully consistent with the official algorithm.

# Task 3 — Make Z compression symmetric with B compression

Current desired behavior:

Subspace iteration uses:

    Z_i = A_i^T Q_i

where:

    Z_i shape = n x l

For current experiments:

    l = 256

We already want Z compression to compress row vectors:

    Z_i[j, :] ∈ R^l

Therefore each TQ vector has dimension:

    d = l = 256

Use the existing Lloyd-Max codebook_d256_b* path.

## Problem

Currently Z compression appears to compress only the inter-node / MPI path, while B compression effectively compresses both:

1. intra-node GPU-to-GPU path
2. inter-node MPI path

Z should be handled similarly.

## Required Z compression design

When --compress-subspace-mode tq is enabled, apply TQ to both Z communication stages:

## Stage A — Intra-node Z compression

Each GPU computes its own local:

    Z_g = A_g^T Q_g

with shape:

    n x l

Then:

1. Treat each row Z_g[j, :] as a vector of length l = 256.
2. Compress row vectors using TQ Lloyd-Max path.
3. Transfer compressed payload from GPU g to the rank-local aggregator GPU, usually GPU0, using peer copy.
4. GPU0 dequantizes each payload.
5. GPU0 accumulates the decoded contribution into rank-local Z.

Conceptually:

    GPU g computes Z_g
    ↓
    row-vector TQ compress on GPU g
    ↓
    cudaMemcpyPeer compressed payload to GPU0
    ↓
    GPU0 dequantizes
    ↓
    GPU0 accumulates into Z_rank

If intra-node compression is disabled, preserve the raw path.

## Stage B — Inter-node Z compression

After rank-local aggregation:

    Z_rank = sum_{g in rank} Z_g

all MPI ranks need the global:

    Z = sum_rank Z_rank

because each rank needs Z for the next local GEMM:

    Y_i = A_i Z

Compressed bytes cannot be summed by MPI_Allreduce.

Therefore, for compressed Z communication, use this structure:

    each rank compresses Z_rank
    ↓
    MPI_Allgather compressed payloads
    ↓
    each rank dequantizes every rank's payload
    ↓
    each rank sums decoded matrices locally into global Z

Do NOT use MPI_Allreduce(..., MPI_SUM, ...) on compressed bytes.

If inter-node compression is disabled, preserve the existing raw FP32 MPI_Allreduce path.

# Important details for Z row-vector compression

Because Z_i is n x l, and we want row-vector compression:

- If the existing TQ device helper compresses columns of a column-major matrix, transpose Z_i logically or physically to l x n.
- Then each column of the transposed matrix corresponds to one original row vector of length l.
- Use d = 256 Lloyd-Max codebook.
- During dequantization, reconstruct the transposed representation and transpose back if needed.

The final global Z must have the same layout and values expected by the existing GEMM path.
