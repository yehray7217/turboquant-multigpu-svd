# OISST SST Anomaly Testcase

This testcase prepares a real climate matrix for `randomized_svd_multigpu_v4` using NOAA OISST daily sea surface temperature.

## Matrix

- Rows: selected ocean grid points
- Columns: daily snapshots
- Entry: SST anomaly after subtracting the temporal mean at each grid point
- Final file: `matrix.f32`
- Format: raw `float32`, row-major, no header

The formal target is `32768 x 8192`. A smaller debug matrix such as `8192 x 4096` can be generated first as `matrix_debug.f32`.

## Preprocessing

Run the script from this directory:

```bash
python3 scripts/prepare_oisst_matrix.py \
    --rows 32768 \
    --cols 8192 \
    --start-date 2000-01-01 \
    --download-missing \
    --raw-dir raw_data \
    --batch-size 2048 \
    --retries 5 \
    --output matrix.f32 \
    --meta meta.json
```

Debug example:

```bash
python3 scripts/prepare_oisst_matrix.py \
    --rows 8192 \
    --cols 4096 \
    --start-date 2000-01-01 \
    --download-missing \
    --raw-dir raw_data \
    --batch-size 2048 \
    --retries 5 \
    --output matrix_debug.f32 \
    --meta meta_debug.json
```

The script:

1. Downloads missing OISST daily NetCDF files from the NOAA NCEI direct-download root into `raw_data/`.
2. Selects a deterministic time window.
3. Flattens `lat/lon` into ocean points.
4. Samples valid ocean points with seed `1234`.
5. Removes the temporal mean per selected grid point.
6. Writes `matrix.f32` and `meta.json`.

If the daily `.nc` files are already cached locally, re-run with:

```bash
python3 scripts/prepare_oisst_matrix.py \
    --rows 8192 \
    --cols 4096 \
    --start-date 2000-01-01 \
    --local-only \
    --raw-dir raw_data \
    --batch-size 2048 \
    --output matrix_debug.f32 \
    --meta meta_debug.json
```

For flaky network sessions, keep `--batch-size` small and increase `--retries`.

Current download root used by the script:

```text
https://www.ncei.noaa.gov/data/sea-surface-temperature-optimum-interpolation/v2.1/access/avhrr/
```

## Sanity Check

The script prints:

- shape and dtype
- `mean abs` and `max abs`
- `has NaN` / `has Inf`
- row-mean residual statistics
- file size check

For an independent SVD sanity check, run this in a Python environment with
NumPy installed:

```bash
python3 scripts/check_oisst_svd.py \
    --file matrix_debug.f32 \
    --m 8192 \
    --n 4096 \
    --k 250 \
    --sample-rows 4096 \
    --sample-cols 2048 \
    --work-dtype float32
```

To also run a full blockwise randomized SVD check:

```bash
python3 scripts/check_oisst_svd.py \
    --file matrix_debug.f32 \
    --m 8192 \
    --n 4096 \
    --k 250 \
    --full-randomized \
    --oversample 6 \
    --n-iter 1 \
    --work-dtype float32 \
    --repeat 50
```

Use `--work-dtype float32` to better match the CUDA rSVD implementation.
The randomized check reports mean/min/stddev when `--repeat` is greater than 1.

## Benchmark Commands

The `exp_turboquant/` folder contains:

- `smoke-debug.slurm` for the debug matrix smoke test
- `ctrl.slurm` for no compression
- `b8-exp.slurm` for TQ 8-bit
- `b4-exp.slurm` for TQ 4-bit

All runs use `--input-file testcases_real_world/OISST/matrix.f32`, `--subspace-iter 1`, and two phases:

- timing with `--no-check-error`
- final-error without `--no-check-error`

For the debug matrix, submit:

```bash
cd exp_turboquant
sbatch smoke-debug.slurm
```

## Notes

- Do not use `--device-random-input` with `--input-file`.
- `matrix.f32` and `meta.json` are generated by the preprocessing script and are intentionally ignored by git.
- `theoretical` and `err ratio` are `n/a` for this real-world testcase; compare raw `Final Reconstruction Error` and runtime/payload reduction instead.
